# ComicAPNG

ComicAPNG 是一款跨平台的 APNG 漫画创建、提取和阅读应用。一个 APNG 帧代表一页漫画，创建、提取和阅读功能都位于同一个桌面窗口中。应用支持 Windows、Linux 和 macOS。

## 主要功能

- 从图片或目录创建 APNG 漫画。
- 提取普通 PNG 或 APNG 中的页面。
- 使用单页或双页模式阅读 APNG 漫画。
- 选择封面、拖动调整页面顺序，并可一次选择多页进行管理。
- 将所有页面放入统一尺寸的固定画布。
- 保持图片宽高比，不拉伸、不裁剪；空余区域保持透明。
- 分别设置封面和正文页面时长，界面使用三位小数的秒数。
- 编辑 EXIF、PNG 文本和自定义元数据。
- 提供简体中文和英文界面。
- 使用统一的深色主题。

## 下载

稳定版本请从 GitHub 仓库的 **Releases** 页面下载。开发或测试版本可在 **Actions** 中选择一次成功的 **Build ComicAPNG** 运行，然后从 **Artifacts** 下载。

目前提供四种构建：

- Windows x64
- Linux x64
- macOS Intel
- macOS Apple Silicon

macOS 构建目前没有使用 Apple Developer ID 签名，也没有经过公证，因此首次打开时可能出现 Gatekeeper 提示。

构建和平台细节请参阅[技术规格（英文）](./tech-specs.md)。

## 使用方法：创建 APNG

1. 打开 ComicAPNG。
2. 在左侧选择“创建”页面。
3. 导入一个或多个图片文件，也可以导入整个目录或直接拖入文件。
4. 选择页面并拖动调整顺序；需要时可移除页面。
5. 选中一页并将其设为封面。导出时封面只会出现一次，并位于第 1 帧。
6. 设置封面和正文页面时长。新项目默认封面为 `10.000` 秒，正文为 `5.000` 秒，每次增减为 `1.000` 秒。
7. 根据需要设置阅读方向并编辑元数据。
8. 单击“导出”，选择 `.apng` 或 `.png` 输出文件。

导出时，每一帧都使用相同的画布尺寸。图片会按比例放大或缩小并居中，不会被拉伸或裁剪；不同宽高比留下的区域为透明像素。

## 使用方法：提取 APNG

1. 打开 ComicAPNG 并选择“提取”页面。
2. 选择一个 PNG 或 APNG 文件，也可以将文件拖入窗口。
3. 选择输出目录。
4. 根据需要启用覆盖已有文件，或在可靠的 ComicAPNG 几何信息存在时恢复原始页面边界。
5. 单击“提取”。

默认输出文件依次为：

```text
1.png
2.png
3.png
...
```

提取不要求 EXIF，也不要求 ComicAPNG 私有元数据。只要输入文件能够被当前解码器正常读取，普通 APNG 文件同样可以提取。没有可靠几何信息时，应用会保留完整画布，不会根据透明区域猜测裁剪范围。

## 使用方法：阅读 APNG

1. 打开 ComicAPNG 并选择“阅读”页面。
2. 选择一个 PNG 或 APNG 文件，也可以将文件拖入窗口。
3. 使用上一页、下一页、缩略图或页码输入框跳转。
4. 使用放大、缩小、适合页面、适合宽度或实际尺寸调整显示。
5. 根据漫画选择从左到右或从右到左的阅读方向，也可以切换单页、双页和全屏模式。

方向键会按照所选阅读方向前进或后退，`Page Up` 和 `Page Down` 也可翻页，`F11` 可切换全屏。应用会在外部设置中保存阅读位置，不会修改漫画文件。

普通漫画阅读不会按照 APNG 帧时长自动翻页。当前版本没有定时播放模式，帧时长主要用于 APNG 文件本身的动画信息。

## 元数据

元数据是可选的，不影响基本的创建、提取和阅读功能。

- EXIF 元数据可保存描述、作者、版权、软件、日期时间、用户注释以及自定义标签。
- PNG 文本元数据可保存发布者、标题或其他键值信息。
- ComicAPNG 私有元数据记录阅读方向、页面时长和页面几何信息，供支持这些信息的功能使用。

输入文件没有元数据是正常情况。格式错误的私有元数据会被忽略，不会阻止普通页面读取。

## 构建状态与开发版本

如需完整的预发布构建测试，请在 GitHub **Actions** 中打开 **Build ComicAPNG**，单击 **Run workflow**，选择 `main` 后运行。工作流会测试并构建四个平台，生成四个 Artifacts，但不会创建标签或 GitHub Release。

发布候选版本使用 `v1.0.0-rc.1` 形式的标签，并自动创建 prerelease。稳定版本使用 `v1.0.0` 形式的标签，并从稳定标签对应的提交重新构建后创建正式 Release。

## 常见问题

- **macOS 阻止打开应用：** 当前构建未签名、未公证，请在确认下载来源可信后按照系统提示手动允许。
- **APNG 文件很大：** APNG 使用完整图像帧和无损压缩，页面多或分辨率高时文件可能明显增大。
- **无法打开输入文件：** 文件可能损坏、扩展名与实际内容不一致，或使用了当前 Pillow 版本不支持的格式。
- **Linux 无法运行：** 自动构建以 Ubuntu 22.04 为基准，不保证兼容所有发行版。
- **看不到元数据：** 元数据本来就是可选内容，缺少元数据不表示文件损坏。
